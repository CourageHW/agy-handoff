# agy-handoff Guidelines

`agy-handoff` exposes local **OpenAI Codex** (`codex`), **Anthropic Claude Code** (`claude`), and **Google Antigravity** (`agy`, default `gemini-4-neon-high`) CLIs as MCP tools (`handoff_*`), subagents (`codex-handoff`, `claude-handoff`, `neon-handoff`), and companion skills.

## Operating Rules

1. **Prefer read-only by default**: Always start reviews, investigations, and debugging handoffs in `read-only` mode and never auto-escalate permissions. Only pass `mode: "workspace-write"` when the user explicitly asks and confirms that the external CLI should modify files (Codex uses OS sandboxing; Claude Code confines built-in file tools with `--restricted` + `acceptEdits` while `Bash` remains unsandboxed).
2. **Pass the workspace root and scoped context**: Always pass `cwd`. When you already identified relevant paths, constraints, or prior findings, pass `context: { files, summary, constraints, acceptanceCriteria }` so external CLIs skip redundant repo-wide scans.
3. **Check execution evidence & retry safely**: Inspect `executionEvidence` (observed tool calls, modified files, workspace git delta, and warnings). Never accept `workspace-write` completion without confirming observed modifications or git diff. Use `handoff_job_retry` only on failed/timed-out `read-only` jobs.
4. **Verify before retrying**: If a handoff fails due to missing binaries, outdated flags, or auth errors, run `handoff_doctor` once and report the exact upgrade/setup command. Optional `engine: "auto"` selects transparently based on installed CLIs, recent failure streaks, and configured routing policy.
5. **Verify findings against local files**: After receiving a review (`structured: true` or free-form), confirm cited files and semantics in local code before recommending or applying fixes (`semanticallyVerified` is always `false` until checked).
6. **3-to-1 Cross-Review & Subagent visibility in Antigravity CLI**: For the default legacy cross-review, run **3 independent reviewers in parallel** (`codex` [default `gpt-6.2-sol high`] + `claude` [default `claude-opus-5-5 high`] + `agy` [default `gemini-4-neon-high high`]) and have the **current session's conversation model** synthesize all 3 into 1 verified report (`3-to-1`). When the user wants inspectable subagent panes (`/agents`, `Alt+J`), check `handoff_config({ action: "get" })` and invoke `codex-handoff`, `claude-handoff`, and `neon-handoff` in parallel with `Role` formatted to include the active model and effort (e.g., `"gpt-6.2-sol high review"`, `"claude-opus-5-5 high review"`, `"gemini-4-neon-high high review"`). Use only one execution path for each reviewer. If the user asks for the other two agents, pass `engines: ["codex", "claude"]` or launch only those subagents. Mention `node <plugin-root>/src/cli.mjs watch` for live terminal monitoring.
7. **Grill-Me Spec Interview & 3-to-1 Collaborative Planning (`handoff_plan`)**: Before planning non-trivial features or refactors, explore the codebase first (never ask what code already answers), then interview the user down each branch of the design tree (`/agy-handoff:handoff-grill-me`). Pass the confirmed spec decisions (`goal`, `decisions`, `requirements`, `nonGoals`, `constraints`, `acceptanceCriteria`, `context.files`) to `handoff_plan` (`/agy-handoff:handoff-plan`) to run `codex` + `claude` + `agy` in parallel (`read-only`) and synthesize a zero-handwaving, TDD-first Master Plan with verified disk file targets.
8. **Write Concrete Task Contracts, Not Persona Prompts**: When delegating or splitting work across external models (`handoff_delegate`, `handoff_review`, subagents), skip role-play/persona boilerplate (e.g., *"You are a senior staff engineer..."*). Instead, specify four concrete elements in every brief:
   - **Objective & Owned Scope**: exact question or files/symbols owned (plus explicit out-of-scope boundaries / YAGNI).
   - **Expected Deliverable**: exact output structure (root cause + `file:line` + minimal patch, interface contract, failing-first test + fix, or severity-ordered defects).
   - **Constraints**: permission boundary (`read-only` vs confirmed `workspace-write`), compatibility/security invariants, and local-first grounding.
   - **Verification Criteria**: exact command(s) or acceptance checks proving completion — and always pass `taskType` plus `context: { files, summary, constraints, acceptanceCriteria }` so `agy-handoff` attaches the matching execution contract and preloads small scoped files automatically.
